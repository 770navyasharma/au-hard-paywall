How this dashboard works

Data flow

Pinot (events + stories tables)
  ↓ GitHub Actions cron · 02:00 IST daily · pulls yesterday
Python puller (3 queries per day)
  ↓ joins + premium filter in pandas
Google Sheet (3 tabs: feed_metrics · paywall_metrics · stories_dim)
  ↓ "Publish to web" as CSV
Dashboard (static HTML, GitHub Pages) → filters client-side

What the dashboard shows

Daily funnel for hard-paywall premium stories pinned on the foryou homepage feed. Positions 5, 13, 21, 27, 28 across 4 feed versions: v2691 (~85%) pins the 4th premium story at position 27; versions 4810, 2694, 4809 (~5% each) pin it at position 28. Positions 5, 13, 21 are common to all.

How each metric is attributed (strict filters)

  • Feed impression / click — Pinot events table has flat columns for story_id, feed_id, feed_version_id, feed_position, screen_name, platform. Filters: screen_name='foryou', feed_id=1838, position IN (5,13,21,27,28), LOWER(platform) IN ('android','ios'). Unique users = DISTINCTCOUNT(user_id).
  • Paywall funnel — flat story_id is populated on PAYWALL_VIEW / PAYWALL_CLICK but NULL on VIEW_ITEM_LIST / BEGIN_CHECKOUT / BUYS. So we resolve story via CASE WHEN story_id IS NOT NULL THEN story_id ELSE REGEXP_EXTRACT(acqSubSource, '[a-f0-9]{24}') END — regex pulls the 24-char ObjectId from the pipe-separated acqSubSource. Additional strict filters:
    • acqSource = 'pay wall | premium' (exact match — excludes e-paper paywall and non-premium)
    • screen_name = 'articleDetailScreenview' for PAYWALL_VIEW / PAYWALL_CLICK
    • screen_name = 'subscriptionScreen' for VIEW_ITEM_LIST / BEGIN_CHECKOUT / BUYS_PREMIUM_SUBSCRIPTION
    • LOWER(platform) IN ('android','ios')
  • Premium story filter — positions 5/13/21/27/28 contain personalized non-premium stories too. After fetching, we join stories table in pandas (Pinot join hits memory limit) and keep only is_premium='true'. Drops ~97% of feed rows as noise.
  • Story title + URL — from stories table: title_hn (Hindi), full_slug → https://www.amarujala.com/<full_slug>, author_firstname_hn + author_lastname_hn.

Daily refresh

Cron runs at 20:30 UTC (02:00 IST next day). It pulls yesterday-IST only — current day is never fetched so numbers are never partial. Idempotent: re-running the same date replaces that date's rows.

Why some numbers may look different from the Pinot console

Premium filter: console queries without is_premium='true' will show much larger numbers because they include personalized non-premium stories at those positions.

Paywall event split: PAYWALL_VIEW total across your cluster includes e_paper_rewarded_ad, e_paper_archive events. We exclude those via acqSource LIKE '%premium%'.

All 3 queries run once per day. Reserved words (date, hour, position) are added/renamed in pandas after the query — never aliased in SQL.

1 · Feed metrics

per day · ~1-2s · 10-15k raw rows before premium filter
SELECT
  event_hour_ist,
  feed_version_id,
  feed_position,
  story_id,
  DISTINCTCOUNT(CASE WHEN event_type='FEED_IMPRESSION' THEN user_id END) AS fi_users,
  DISTINCTCOUNT(CASE WHEN event_type='FEED_CLICK'      THEN user_id END) AS fc_users,
  COUNT(CASE WHEN event_type='FEED_IMPRESSION' THEN 1 END) AS fi_events,
  COUNT(CASE WHEN event_type='FEED_CLICK'      THEN 1 END) AS fc_events
FROM events
WHERE event_type IN ('FEED_IMPRESSION','FEED_CLICK')
  AND feed_id = 1838
  AND feed_position IN (5,13,21,27,28)
  AND event_date_ist = 'YYYY-MM-DD'
  AND screen_name = 'foryou'
  AND LOWER(platform) IN ('android','ios')
  AND story_id IS NOT NULL
  AND story_id != ''
  AND story_id != 'LOYALTY'
GROUP BY event_hour_ist, feed_version_id, feed_position, story_id
LIMIT 100000

2 · Paywall funnel metrics

per day · ~2-3s · PV / PC / VIL / BC / BUYS unique users per (hour, story)
SELECT
  event_hour_ist,
  -- VIL / BC / BUYS have story_id NULL; fall back to regex on acqSubSource
  CASE
    WHEN story_id IS NOT NULL AND story_id != '' AND story_id != 'null'
      THEN story_id
    ELSE REGEXP_EXTRACT(
      JSON_EXTRACT_SCALAR(metadata, '$.acqSubSource', 'STRING', ''),
      '[a-f0-9]{24}'
    )
  END AS resolved_story_id,
  event_type,
  DISTINCTCOUNT(user_id) AS unique_users
FROM events
WHERE event_date_ist = 'YYYY-MM-DD'
  AND LOWER(platform) IN ('android','ios')
  -- exact match — excludes e-paper paywall + non-premium entries
  AND JSON_EXTRACT_SCALAR(metadata, '$.acqSource', 'STRING', '') = 'pay wall | premium'
  -- canonical screen per event type
  AND (
    (event_type IN ('PAYWALL_VIEW','PAYWALL_CLICK')
      AND screen_name = 'articleDetailScreenview')
    OR
    (event_type IN ('VIEW_ITEM_LIST','BEGIN_CHECKOUT','BUYS_PREMIUM_SUBSCRIPTION')
      AND screen_name = 'subscriptionScreen')
  )
GROUP BY event_hour_ist, resolved_story_id, event_type
LIMIT 200000

Pandas pivots this long form into wide columns: pv_users, pc_users, vil_users, bc_users, buys_users.

3 · Story dimension

once per run (not per day) · batch IN clause
SELECT
  story_id, title_hn, title,
  author_firstname_hn, author_lastname_hn,
  category_title_hn, full_slug, is_premium
FROM stories
WHERE story_id IN ('<id1>', '<id2>', ...)
LIMIT 100000

In pandas: author = firstname_hn + ' ' + lastname_hn, url = 'https://www.amarujala.com/' + full_slug. Then premium filter drops ~1380 non-premium stories/day, keeping ~10 pinned premium stories.

Post-processing in Python

  • Add date column + rename event_hour_ist→hour, feed_position→position (Pinot reserves date/hour/position as keywords — can't alias in SQL).
  • Join stories dim → filter to is_premium='true' only.
  • Write 3 tabs to Google Sheet via service account. Idempotent per date.
